[ ] A7. Телефон и в РЕГИСТРАЦИИ, и в /account: дропдаун стран вместо текущего auto-guess-only

        Давида). Дефолт дропдауна — страна посетителя по IP (см. блок B).

История входов (см. блок C) на /account НЕ показывается — только в админке.

D. SUPERADMIN
=====================================================================
Контекст: сейчас (B6, 2026-08-06) роль Admin НЕИЗМЕНЯЕМА в принципе — снять Admin с кого угодно
запрещено безусловно, кем угодно ("The Admin role can only be changed directly in the database").
Удаление Admin-аккаунта тоже запрещено всем в панели. Задача Давида — сделать для одного человека
(SuperAdmin) исключение из этого блока.

[ ] D1. Колонка User.IsSuperAdmin (bool, default false) + миграция.
[ ] D2. Ровно один SuperAdmin, заводится ТОЛЬКО через сид (seed) — никакого UI/эндпоинта на
        назначение SuperAdmin. Предполагаю: это тот же существующий сид-админ
        (admin/admin@haytravel.local), а не отдельный второй аккаунт — если Давид имел в виду
        другое, поправит.
[ ] D3. SuperAdmin (и только он, ровно 1 пользователь) видит и может ВСЁ: удалить аккаунт
        другого админа, повысить любого до Admin, понизить админа. Обычные админы: как раньше
        создают/редактируют продукты, могут менять роль пользователя только между
        Regular/TourManager — в их RoleSelect опция "Admin" вообще не отображается и не
        выбирается. Обычный админ НЕ МОЖЕТ сделать кого-либо Admin ни при каких условиях —
        только SuperAdmin. Backend отдаёт 403, если не-SuperAdmin всё же пришлёт roleId=Admin
        (защита не только на UI, IDOR/прямой запрос тоже должен быть отбит).
[ ] D4. Самозащита: SuperAdmin не может удалить/понизить сам себя через панель (существующий
        self-guard "нельзя удалить себя" остаётся в силе и для него) — если Давид хочет иначе,
        скажет отдельно.
[ ] D5. Модалка подтверждения при повышении пользователя до роли Admin — сейчас смена роли это
        обычный select без подтверждения вообще (проверено, RoleSelect/UsersTable). Добавить
        confirm-модалку (по образцу UserDangerZone) конкретно на переход к роли Admin.
[ ] D6. IsSuperAdmin НИКОГДА не уходит на фронт в DTO чужих пользователей (UserInfoModel/
        UserDetailInfoModel — список/карточка ДРУГОГО пользователя никогда его не содержат,
        по всей админке нельзя узнать кто ещё SuperAdmin). Собственный статус SuperAdmin
        текущий пользователь узнаёт через тот же канал, что уже несёт role — JWT-claim/
        собственный auth-профиль при логине, а не через список пользователей. Именно так
        включаются кнопки "удалить admin"/"promote в admin" и опция "Admin" в дропдауне —
        только у самого SuperAdmin, в его собственной сессии.
[ ] D7. Email SuperAdmin (сид) меняется на davit.shahinyan09@gmail.com — правка сида +
        UPDATE существующей строки в LocalDB. Давид подтвердил (2026-08-09): менять и на
        Azure SQL (прод) сейчас же, тем же UPDATE.

АРХИТЕКТУРНАЯ СПЕКА (backend-architect, 2026-08-09) — готова, детали см. в истории сессии.
Ключевые решения после уточнений у Давида:
  - Гео-IP база (DB-IP City Lite, .mmdb, читается пакетом MaxMind.GeoIP2 без аккаунта) —
    СКАЧИВАЕТСЯ ПРИ СТАРТЕ БЭКЕНДА (не коммитить в репо), graceful degradation если файла нет.
  - SuperAdmin НЕ может через ChangeRole снять/понизить свою же роль Admin (согласовано).
  - Guard берёт IsSuperAdmin из БД (не из JWT-claim) — защита от IDOR/прямого запроса.
  - IsSuperAdmin НИКОГДА не попадает в DTO чужих пользователей; свой статус — через JWT-claim
    "is_super_admin" (только если true), тем же каналом, что уже несёт role.
  - Новый AccountController (self-service, PATCH api/Account/Phone) — отдельно от AuthController
    (телефон это profile-данные, не credential/auth-состояние).
  - Новый GeoController (анонимный, GET api/Geo/Country) — страна+город по IP запроса,
    БЕЗ dialCode (это зона libphonenumber-js на фронте, не дублируем на бэке).
  - LoginHistory пишется только в LoginAsync (не в RefreshAsync — ротация не считается логином).
  - Формат хранения телефона — БЕЗ ведущего "+", колонка nvarchar(15) не меняется.
