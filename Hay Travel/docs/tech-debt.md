# Технический долг

Отложенные решения — то, что сознательно не сделано сейчас, чтобы не блокировать текущую
задачу. При каждой новой фиче/сессии проверять, не относится ли она к пункту ниже, и напоминать
Давиду.

## SEO-метатеги при переезде с Netlify на self-hosted (netcup)

**Что было:** `netlify/edge-functions/seo-meta.ts` — Netlify Edge Function, подставляет
админом заданные SEO-поля (title/description/OG) в `<head>` HTML на лету, до отдачи ответа.
Работает только на Netlify, на nginx не переносится автоматически.

**Что сейчас (2026-08-15):** при переезде фронтенда на netcup VPS + nginx эта функция
отложена — статические теги из `index.html` остаются, динамический SEO из админки временно не
подставляется в HTML-ответ (влияет на превью в мессенджерах/соцсетях и краулеры, сам сайт
работает нормально).

**Как закрыть, когда возьмёмся:** написать маленький сервис/скрипт (Node или на самом
бэкенде), который подставляет meta-теги в HTML на лету — аналог edge function, но под nginx
(`sub_filter` + upstream-сервис, либо SSR-прослойка). Согласовать подход через `architect`
перед реализацией — не отдавать сразу в `frontend-developer`.

**Статус:** отложено по решению Давида 2026-08-15, спросить при следующей фронтенд-сессии.

## Загруженные изображения: нет бэкапа и нет удаления осиротевших файлов

**Что сейчас (2026-08-15):** `api/Upload/Image` (см. `backend-api.md`) пишет оригинал+WebP на
диск сервера (`/opt/haytravel/uploads`) и никогда сам их не удаляет — ни когда админ заменяет
картинку новой (старый файл остаётся мёртвым грузом), ни когда удаляется тур/точка/место,
использовавшие эту картинку. Файлы не входят ни в один автоматический бэкап (только БД имеет
point-in-time восстановление через SQL Server).

**Как закрыть, когда возьмёмся:** (1) удаление осиротевших файлов — при замене/удалении записи
со старым URL, если он `/uploads/*`, удалять оба файла (оригинал+webp) с диска; (2) бэкап —
periodic `rsync`/`tar` каталога `uploads/` на сервере, или снапшот диска на стороне netcup.

**Статус:** сознательно отложено по решению Давида 2026-08-15 при постановке фичи загрузки
файлов — не блокирует использование, просто диск будет постепенно расти мёртвыми файлами без
уборки.

## Region/GetRegionsClient грузится сразу на двух языках

**Что сейчас (2026-08-16):** главная всегда тянет `Region/GetRegionsClient` на `languageCode=1`
И `=2` сразу, хотя рендерится только один язык за раз — осознанное решение с 2026-08-15
(комментарий в `shared/api/regions.ts`), не дубль в строгом смысле (разные параметры запроса).
Каждый запрос сам по себе быстрый (~100-200 мс) и не был причиной жалобы «сайт медленный», но
лишняя нагрузка на бэкенд/БД остаётся.

**(Закрыто 2026-08-16, см. CHANGELOG):** `Tag/GetForClient` и `SiteSettings/GetPublic?group=6`,
которые реально дублировались (два независимых вызова одного и того же запроса на одной
странице) — `getTagCatalog`/`getContentText` получили session-кэш по языку.

**Как закрыть, когда возьмёмся:** либо кэшировать оба языка сразу и не дёргать заново при смене
языка (тогда двойной запрос оправдан), либо грузить только активный язык и рефетчить при
переключении.

**Статус:** не входило в подтверждённый Давидом объём фикса скорости 2026-08-16, кандидат на
отдельный заход.

## ~~Список туров в админке (`GetAll`) тянет полный детальный граф на каждый тур~~ — закрыто 2026-08-16

`IncludeTourAdminListGraph` (`TourGraphQueryExtensions.cs`) — новый облегчённый граф специально
для `GetAllAsync()` (дашборд, страница продуктов), по аналогии с клиентским `IncludeTourCardGraph`
(D-11). Тот же набор Tour-уровневых коллекций, что у полного `IncludeTourGraph`
(`Translations`/`AdditionalExpenses`/`Notes`/`TourRegions`/`TourTags`), но БЕЗ по-дневного
контента — `TourDetails.TourDay` остаётся Included как голая ссылка (маппер строит `tourDays`
через `Select(td => td.TourDay)`, без Include это был бы `null`), но `TourDay.Translations`/
`GalleryImages`/`RoutePoints` больше не тянутся: список читает только `tourDays.length`
(проверено по факту — `DashboardPage`/`StatCards`/`ProductsPage`/`ProductsTable`/
`filterProducts` грепнуты на предмет использования полей `TourInfoModel`, содержимое дня нигде
не читается). `TourInfo.InitUpdate` (открытие ОДНОГО тура на редактирование) остался на полном
`IncludeTourGraph()` + `AsSplitQuery()` — форма редактирует все дни/фото/точки маршрута
целиком, ей действительно нужен весь граф.
