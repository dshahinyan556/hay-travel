# Модель продукта (тур / экскурсия)

Продукт — это тур или экскурсия. Обе сущности хранятся как `Tour` с полем `Type`.

## Домен: тур vs экскурсия
- **Экскурсия** — ровно 1 день (без ночёвки).
- **Тур** — 2 дня и более (минимум 1 ночёвка).
- Тип **неизменяем после создания** (тур нельзя превратить в экскурсию и наоборот). В форме редактирования тумблер типа заблокирован; бэкенд тоже отклоняет смену типа (400).

## Форма (`src/features/admin/tour-form/`)
Состоит из всегда видимой шапки (`TourFormHeader`) и карточки с вкладками. Состояние — `useReducer` (`useTourForm`), без form-библиотек. Конвертация wire ↔ view-model только в `lib/tourMapper.ts`.

**Шапка**: тип, главная картинка (URL), заголовок/краткое описание/описание/длительность (RU+EN), публикация, цена.

**Вкладки**:
- **Тур**: `Дни` (аккордеон дней) + `Организационные детали` + `Ограничения` + `Доп. расходы`.
- **Экскурсия**: вкладки `Дни` **нет**. Единственный день = сам тур, поэтому:
  - цена — редактируемый инпут прямо в шапке;
  - точки маршрута и галерея единственного дня — секциями под шапкой;
  - заголовок/описания шапки автоматически становятся текстами дня (унификация при отправке — `dayTexts()` в `tourMapper`), чтобы не заполнять дважды.

## Цена
- **Тур**: цена в шапке — read-only сумма цен всех дней (цена вводится в каждом дне).
- **Экскурсия**: цена вводится в шапке и пишется в единственный день.
- На бэке `TotalPrice` считается на запись (Σ цен дней) при create/update.

## Валидации (фронт + бэк)
Обязательные/блокирующие:
- заголовок продукта (RU) и главная картинка;
- для тура — минимум 2 дня; заголовок RU каждого дня (у экскурсии день наследует шапку — не проверяется отдельно);
- **цена не может быть отрицательной** (каждый день);
- **минимум 1 точка маршрута** в каждом дне (в т.ч. в единственном дне экскурсии);
- **тип неизменяем** при редактировании.

Фронт: ошибки скрыты до первой попытки сохранения (`hasAttemptedSubmit`), затем показываются вживую (`lib/validation.ts`). Бэк дублирует правила в `TourValidationService` (работает и на create, и на update) + запрет смены типа в `TourUpdateService`.

## Архив
Мягкое удаление (soft-delete) через флаг `IsArchived` — отдельно от `IsActive` (публикация на сайте):
- **В архив**: `SetArchived(id, true)` — тур исчезает из основного списка (`GetAll`), появляется в `GetArchived`.
- **Восстановить**: `SetArchived(id, false)`.
- **Удалить окончательно**: `DeleteTour(id)` — безвозвратно, только из архива, с подтверждением в UI.

## Избранное (2026-08-02)
Отдельно от `IsActive`/`IsArchived`: `Tour.IsFeatured`(bool) + `FeaturedSortOrder`(int) — показ в секции «избранное» на главной публичного сайта. Управляется только через `PATCH SetFeatured`/`PATCH ReorderFeatured` (`api/Tour`), не через `UpdateTour`. Не более 6 туров одновременно — сервер отклоняет 7-й (`TooManyFeaturedTours`/2011), админка (`Продукты → Избранные`) дизейблит сердечко на остальных турах, когда лимит достигнут. Публичная секция показывает **ровно то, что отмечено**, в заданном порядке — без «первых N туров» как фолбэка и без плейсхолдеров при пустом наборе (секция целиком скрыта, если ничего не отмечено).

## Переводы
Каждое текстовое поле двуязычное (RU+EN). На бэке — плоский список `{Type, LanguageCode, Value}` (2 строки на поле). В форме — `Localized {ru, en}`. Разворот/сборку делает только `tourMapper.ts`.

Двуязычные упорядоченные списки (точки маршрута дня, орг.детали, ограничения тура) используют общий тип `LocalizedListItem` и общий компонент `LocalizedListEditor`. Реордер — drag-and-drop мышью/тачем/клавиатурой через общий примитив `shared/ui/SortableList.tsx` (+`DragHandle`, на `@dnd-kit`), не кнопки ▲▼ (убраны 2026-08-01). Дни тура (`TourDaysEditor`/`TourDayCard`) и галерея дня (`GalleryImagesEditor`) используют тот же примитив. Редьюсер адресует реордер по индексам (`{fromIndex, toIndex}` → `arrayMove`), а не по направлению — единственное намеренное исключение из правила «списки адресуются по `key`, не по индексу» (см. `tourFormReducer.ts`).

**Автодополнение из справочников (2026-08-01).** Точки маршрута, орг.детали, ограничения
(`LocalizedListEditor`) и доп.расходы (`AdditionalExpensesEditor`) подсказывают существующие
записи справочника, пока печатаешь — это не `Select` (значение не ограничено списком): свободный
текст остаётся всегда, подсказка — только ускоряющий шорткат. Компонент `shared/ui/SuggestInput.tsx`
(текстовый `Input` + `Popover`-панель, тот же паттерн наведения-и-клика, что у листбокса `Select`)
подключён к RU- и EN-полю по отдельности, список кандидатов — по подстроке (`includes`,
регистронезависимо), пустой ввод при фокусе показывает все варианты (до 20). Выбор подсказки
заполняет **сразу оба языка** через `onChangeText`/`onChangeDescription` — поле остаётся
редактируемым дальше. Источник подсказок — три каталога (`Place`/`ExpenseTemplate`/
`TourNoteTemplate`, последний фильтруется по `TourNoteType` для орг.деталей и ограничений
раздельно), грузятся в лоадере `tourCreateLoader`/`tourEditLoader` параллельно с самим туром
(`CatalogSuggestions` в `types/form.ts`), маппинг — `placesToSuggestions`/
`expenseTemplatesToSuggestions`/`noteTemplatesToSuggestions` в `lib/tourMapper.ts` (переиспользует
`readLocalized(translations, 0)` — каталоги всегда кодируют название переводом `type: 0`).
