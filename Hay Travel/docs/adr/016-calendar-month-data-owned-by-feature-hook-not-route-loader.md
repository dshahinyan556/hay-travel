# ADR 016 — Данные месяца календаря держит хук фичи, а не route loader

Дата: 2026-08-11. Автор: `frontend-architect`. Статус: принято.
Связанные: [spec 003](../specs/003-calendar-frontend.md), `app/router.tsx` (доктрина «data mode»).

## Контекст

Весь проект на React Router v8 в «data mode»: данные экрана грузит `loader`, компонент читает
`useLoaderData`, после мутации вызывается `revalidator.revalidate()`. Так сделаны
`ProductsPage`, `CatalogPage`, `UsersPage`, `SettingsPage`.

Админ-календарь ломает предпосылку этого паттерна. Loader грузит данные **на навигацию**, а
переключение месяца стрелкой — это не навигация: пользователь листает вперёд-назад по десятку
месяцев за секунды, оставаясь на одном экране. Варианты «как загрузить месяц»:

1. **Месяц в URL (`/admin/calendar?month=2026-09`), данные — в loader.** На каждое нажатие
   стрелки меняется URL → перезапускается loader → пока он не завершится, экран показывает
   старые данные без индикации, а `revalidator` дёргает и все прочие запросы лоадера (список
   туров, список правил), которые от месяца не зависят. Плюс: кнопка «Назад» листает месяцы,
   что в админке скорее мешает (Назад ожидаемо уводит со страницы, а не на август).
   Кэша нет: возврат на предыдущий месяц — снова сеть.
2. **Месяц в локальном стейте, данные — в loader** — невозможно: loader не видит локальный стейт.
3. **Месяц в локальном стейте, данные — в хуке фичи с кэшем.** Принято.

## Решение

- `calendarLoader` грузит только то, что от месяца НЕ зависит и нужно для первого кадра:
  список туров (`getAllTours`) и список правил (`getClosureRules`). Это ровно тот же контракт,
  что у `catalogLoader` — ошибка не глотается, летит в `AdminErrorBoundary`.
- Текущий месяц — `useState` в `CalendarPage` (тот же выбор, что у активной вкладки в
  `CatalogPage`: экранное состояние, не адресуемое состояние).
- Данные месяца — хук `useCalendarMonth`: `Map<'YYYY-MM', MonthBundle>` в `useRef`, дедупликация
  параллельных запросов, префетч следующего месяца после успешной загрузки текущего,
  `invalidateAll()` после любой мутации правил.
- В один поход берутся сразу `GetCalendar(y, m)` и `Order/GetAll?from=&to=` на границы месяца —
  так панель дня открывается без сети (детали заказов уже в кэше), а число запросов на
  просмотренный месяц остаётся 2, а не 2 + N открытых дней.

## Последствия

- Календарь — единственный экран админки, который читает данные не из `useLoaderData`.
  Расхождение с общим паттерном намеренное и описано в шапке `useCalendarMonth.ts`; сам список
  правил при этом остаётся лоадерным и обновляется через `revalidator`, так что «два источника»
  не смешиваются в одних и тех же данных.
- URL календаря не несёт месяц: ссылку «открой ноябрь» переслать нельзя. Для внутренней панели
  на 1–3 сотрудников это приемлемая цена; если понадобится — месяц добавляется в query string
  без переезда загрузки в loader.
- Загрузка всех заказов месяца одним запросом предполагает десятки, максимум сотни строк.
  Порог зафиксирован в спецификации: при устойчивом превышении ~500 заказов в месяц панель дня
  переводится на точечный `Order/GetAll?from=day&to=day`, интерфейс хука при этом не меняется.
