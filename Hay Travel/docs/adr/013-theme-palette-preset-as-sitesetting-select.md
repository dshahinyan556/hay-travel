# ADR 013. Палитра-пресет и дефолт темы — ключи SiteSetting c типом Select, а не отдельная сущность

- **Дата:** 2026-08-11
- **Статус:** Accepted (решение Backend Architect по задаче design-settings; палитру/шрифт как визуал решают дизайнер и frontend-architect отдельно)
- **Контекст этапа:** дизайн-настройки (кураторские палитры + мягкий дефолт dark/light)

## Контекст

Нужно хранить и отдавать через API две управляемые из `/admin/settings` вещи:

1. **Активный пресет палитры.** Решено Давидом: не свободный конструктор цветов, а
   небольшой набор (3-5) кураторских пресетов, определённых дизайнером. Один из них —
   текущий обсидиан+золото. Админ только **выбирает** активный, не редактирует состав.
2. **Мягкий дефолт режима dark/light** для новых посетителей. Клиентский переключатель
   темы остаётся рабочим — это seed-значение, а не жёсткая блокировка.

Развилки:
- **D-1.** Пресеты палитр — новый ключ `SiteSetting` или отдельная сущность-каталог
  (как `Place`/`ExpenseTemplate`/`TourNoteTemplate`)?
- **D-2.** Куда положить ключи — новый `SiteSettingGroup` или существующий `Branding`?
- **D-3.** Значение пресета/режима — свободная строка или ограниченный набор?

## Решение

**D-1. Ключ `SiteSetting`, а не сущность.** Два новых ключа:
`theme.activePalette` (значение = id пресета) и `theme.defaultMode` (значение = `dark`/`light`).
Состав допустимых пресетов — статический каталог в коде (`ThemePaletteCatalog`), ровно как
состав ключей настроек живёт в `SiteSettingCatalog` (ADR 002).

**D-2. Новая группа `SiteSettingGroup.Theme`.** Инвариант «Key начинается с имени группы в
нижнем регистре + точка» соблюдён: группа `Theme` → ключи `theme.*`. Отдельная карточка в
админке строится автоматически из ответа сервера, как это уже было с группой `Content`.

**D-3. Ограниченный набор + новый тип контрола `SettingValueType.Select`.** Значение
валидируется на сервере против списка допустимых опций; неизвестный id/режим → `400`.
Опции (id + подпись) отдаются админке из каталога вместе с метаданными ключа — фронт не
хардкодит список пресетов, как не хардкодит список ключей.

## Обоснование

- **Пресеты не CRUD-ятся админом.** Реальные цвета пресета живут в CSS фронта
  (`index.css`), их пишет дизайнер/frontend-developer. Админ выбирает один id — это ровно
  «одно сохранённое значение поверх каталога в коде», паттерн ADR 002, а не запись-сущность,
  которую заводят/удаляют/переупорядочивают. Сущность-каталог (`Place` и др.) существует
  потому, что её строки **создаёт и редактирует админ**; здесь этого нет.
- **Отдельная таблица палитр стала бы вторым источником правды**, который разъедется с CSS:
  добавить пресет всё равно нельзя без деплоя фронта (новые CSS-переменные), поэтому «пресет
  без деплоя» недостижим — тот же аргумент, что в ADR 002 про метаданные ключей.
- **Ограниченный набор вместо свободной строки** — потому что произвольный id палитры/режима
  не имеет смысла на сайте (нет соответствующего CSS) и должен отбиваться как ошибка ввода,
  а не сохраняться молча. Валидация по каталогу — тот же приём, что «неизвестный Key → 400».
- **Новый `SiteSettingGroup.Theme` вместо `Branding`** — `Branding` сегодня это только
  логотип; тема/палитра/режим — отдельная смысловая карточка. Дешевле, чем растягивать
  смысл `Branding`, и не ломает инвариант «префикс ключа = имя группы».
- **`Select` встроен в существующий механизм**, а не сделан отдельным эндпоинтом: `GetAll`/
  `Update`/`GetPublic` уже generic по ключам, добавление типа контрола и поля `Options` в
  метаданные ничего в контроллере/репозитории не меняет.

## Последствия

- **Миграция не нужна вообще** (следствие ADR 002): новые ключи — строки каталога, новые
  члены enum и поле DTO `Options` — только код. Ни схемы, ни сида.
- Добавить новый пресет позже = одна строка в `ThemePaletteCatalog` + соответствующий CSS на
  фронте. Бэку — без деплоя миграций, только редеплой.
- Оба ключа `IsPublic = true` и язык-нейтральны (`IsTranslatable = false`): id/режим не
  зависят от языка. `GetPublic` отдаёт их клиентскому сайту как обычные публичные значения.
- Валидация значения Select — новое правило в `SiteSettingsValidationService` и новый код
  `GlobalErrorCode.SiteSettingValueNotAllowed = 2013`.
- `theme.defaultMode` — только seed: применение на клиенте (localStorage-приоритет, рабочий
  переключатель) — зона frontend-architect, вне этого ADR.
