# ADR 002. SiteSettings: метаданные ключа — в коде, БД хранит только значение

- **Дата:** 2026-07-29
- **Статус:** Accepted (решение Давида по развилке D-1 от 2026-07-29; реализовано в 3.1)
- **Контекст этапа:** 3.1 (SiteSettings)

## Контекст

Замороженное решение: настройки сайта — key-value с переводами и флагом публичности,
**новая настройка не должна требовать миграции**. Набор: hero-блок целиком, контакты
и соцсети, логотип, SEO.

Метаданные ключа (группа, тип контрола, переводимость, публичность, порядок, дефолт)
должны где-то жить: либо колонками в таблице, либо в коде.

## Решение

Таблица `SiteSetting` хранит только `Key` + `Value` (+ `SiteSettingTranslation`).
Всё остальное — в статическом каталоге `ATTours.Common/Infrastructure/SiteSettings/SiteSettingCatalog.cs`.
Слияние «каталог ⟵ БД» выполняет `SiteSettingsInfo` в слое Service; ключ, отсутствующий
в БД, возвращается с дефолтом каталога и `Id = 0`.

## Обоснование

- Метаданные никем не редактируются. В БД они стали бы вторым источником правды,
  который неизбежно разъедется с кодом.
- `IsPublic` — свойство безопасности. Тумблер в админке, публикующий приватный ключ,
  создаёт риск утечки; такое изменение должно проходить ревью в коде.
- Требование «без миграции» выполняется: добавление настройки = одна строка в каталоге.
  Сид/`HasData` не нужны вовсе.
- Фронт всё равно обязан знать ключ, чтобы отрисовать поле, поэтому «настройка без
  деплоя» на практике недостижима даже при хранении метаданных в БД.

## Последствия

- Админка **не может** завести произвольный ключ: неизвестный `Key` в `Update` →
  `400 GlobalErrorCode.SiteSettingKeyUnknown`.
- Добавление настройки требует деплоя бэка (но не миграции и не сида).
- `MappingProfile` обращается к статическому каталогу, чтобы заполнить метаданные в
  `SiteSettingInfoModel` — осознанное исключение из правила «маппер только перекладывает
  поля»; каталог — константа, без DI и состояния.
- Значение разрешается по правилу `перевод(язык) ?? Value ?? DefaultValue` в слое Service —
  та же форма, что и замороженное `override ?? шаблон` для справочников этапа 3.4.
  Побочный эффект: добавление третьего языка не ломает сайт — до заполнения переводов
  отдаётся язык-нейтральное значение вместо `null`.
