0. РЕШЕНИЯ ДАВИДА (зафиксировано в диалоге 2026-08-29, менять только по его слову)
================================================================================
0.1  Форма продукта (create/edit) переводится на DataEntryScreenLayout (шаблон A)
     + кнопка удаления в control zone = «В архив» (мягкое удаление). Окончательное
     удаление остаётся только из архива в списке.
0.2  Трансфер = ТРЕТИЙ TourType (Transfer = 3), отдельной сущности НЕТ.
0.3  Трансферы живут в том же экране «Продукты» (фильтр/вкладка по типу),
     отдельного пункта меню и отдельного права доступа НЕ создаём.
0.4  У трансфера из «богатства» тура остаётся ТОЛЬКО главная картинка + участие в
     «Избранном». НЕТ: галереи, регионов, тегов, скидки, дней, орг.деталей,
     ограничений, доп.расходов.
0.5  Лимит «Избранного» расширяется 6 → 9 (бэк + фронт).
0.6  Цена предопределённого трансфера — по классам авто (справочник), у каждого
     класса на каждом трансфере ДВЕ цены: «в одну сторону» и «туда-обратно»
     (отдельное поле, не ×2).
0.7  Классы авто — новый общий справочник (вкладка в Справочниках): название RU/EN,
     вместимость (мест), лимит багажа (единиц), сортировка.
0.8  Пункты маршрута (откуда / стопы / куда) — свободный текст с подсказками из
     справочника Place (SuggestInput), НЕ строгий Select.
0.9  Время подачи трансфера — обязательное, хранится отдельным полем (не текстом).
0.10 Предопределённый трансфер = обычная бронь (корзина → заказ с ценой).
     Предоплата — опция, которую ставим мы (как у тура: RequiresPrepayment).
0.11 Кастомный трансфер = заказ со статусом «Запрос», цена 0, требует ЛОГИНА
     (как обычная бронь). Отдельной сущности-заявки и отдельного экрана НЕТ.
0.12 Кастомная заявка: маршрут (откуда/куда/стопы, drag-n-drop) + дата и время
     подачи + обратный рейс (своя дата+время) + пассажиры + багаж + желаемый класс
     авто + комментарий.
0.13 Багаж: «средний чемодан» = 3 единицы, «большой» = 5 единиц, «другое» — текст.
     Заполнять НЕ обязательно; если заполнено — ОБЯЗАТЕЛЬНО проверять против
     лимита багажа выбранного класса авто.
0.14 Если пассажиров больше, чем вмещает любой класс авто — форма автоматически
     переводится в кастомную заявку без цены («согласуем транспорт и цену»).
0.15 Публично трансферы видны ТОЛЬКО на /transfers (+ секция избранного на
     главной). В общий каталог туров/экскурсий и его фильтры НЕ попадают.
     У предопределённого трансфера есть своя страница /transfers/:id.
0.16 НОВОЕ ПОЛЕ «Формат» — только для тура/экскурсии (у трансфера его нет):
     радио «индивидуальный / групповой / оба». Показывается на карточке и в
     деталях продукта на публичном сайте.
0.17 Индивидуальный формат = текущее поведение цены: фикс за группу + тирная
     наценка 1-4 / 5-6 / 7+ (7+ — цена скрыта, «по запросу»).
0.18 Групповой формат = цена ЗА ЧЕЛОВЕКА × кол-во гостей, БЕЗ тиров и БЕЗ
     «7+ скрыто». Ограничитель — только свободные места.
0.19 Групповой формат имеет «мест на выезд» — ОДНО число на весь продукт,
     остаток считается по паре (дата + время старта).
0.20 Слот без свободных мест: показать «На этот день свободных мест нет,
     попробуйте выбрать другую дату» + бэк отклоняет перебронирование.
0.21 Время начала продукта (кроме трансфера) — КОЛЛЕКЦИЯ предопределённых времён,
     задаёт админ; клиент на сайте выбирает одно из них и изменить не может.
     Минимум 1 время обязательно (валидация фронт + бэк). Существующим продуктам
     миграция проставляет 09:00.
0.22 Кастомные сохраняемые фильтры в списке заказов — ОТЛОЖЕНО, вернёмся позже
     (влияние заказов-«Запросов» на статистику дашборда тоже разбираем потом).
0.23 Уточнено 2026-08-29 после мокапа: справочник городов НЕ заводим, но фильтры
     «откуда / куда» на /transfers ОСТАЮТСЯ. Источник значений — сами точки From/To
     уже заведённых трансферов (уникальные значения), без новой сущности.
0.24 Правка мокапа: поля обратного рейса выровнять по сетке полей «туда» (были
     смещены вправо отступом рамки).
0.25 Фильтры «Откуда / Куда» на /transfers показываются ВСЕГДА (Давид, 2026-08-29):
     никаких порогов «появляются с N-го маршрута» и скрытия фильтра с одним значением.
0.26 Цена за группу ПРЯЧЕТСЯ при формате «Групповой» (Давид, 2026-08-29) — но так,
     чтобы ничего не сломалось: у тура TotalPrice остаётся суммой цен дней.
0.27 Правила закрытия дат ДОЛЖНЫ проверяться и для трансферов, плюс отдельная фича:
     в календаре можно закрыть отдельно трансферы (как отдельный тип продукта).
0.28 Время старта — СТРОГО обязательно для тура и экскурсии, и на фронте, и на бэке.
     Миграция удаляет ТОЛЬКО посеянные времена 09:00 (строки TourStartTime).
     Сами продукты и заказы НЕ трогаются — Давид подтвердил явно.
0.29 ОБЩЕЕ ПРАВИЛО ПРОЕКТА: всё, что валидируется на фронте, обязано валидироваться
     и на бэке — фронтовая валидация это UX, а не защита от прямых запросов к API.
