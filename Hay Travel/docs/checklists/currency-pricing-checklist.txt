CHECKLIST: Календарь-лимит 3 мес / Мультивалютность / Тирные цены по кол-ву мест
Начато: 2026-08-06. Уточнено с Давидом через 2 раунда AskUserQuestion — см. решения ниже.

=== ЗАФИКСИРОВАННЫЕ РЕШЕНИЯ ===
1. Календарь бронирования (DatePicker.tsx в BookingCard.tsx) — максимум сегодня + 3
   календарных месяца (тот же день месяца), даты после — недоступны для выбора.
2. Валюты: AMD (база, драм, ֏), USD ($), EUR (€), RUB (₽).
3. Курс — Центробанк Армении (CBA), официальный источник.
   Реальный контракт (проверено WebFetch 2026-08-06, не выдумано):
   - SOAP-сервис https://api.cba.am/exchangerates.asmx, операция ExchangeRatesLatest
     (SOAP 1.1/1.2 POST). Есть также ExchangeRatesLatestByISO.
   - Ответ: CurrentDate + Rates[] из {ISO, Amount, Rate, Difference}.
   - ВАЖНО: Rate — это курс за Amount единиц валюты (не всегда 1, у некоторых валют
     котировка за 100/1000). Реальный курс за 1 ед. = Rate / Amount. Это должно быть
     учтено в парсинге, иначе конвертация будет в разы неверной.
4. БД: таблица курсов с полями (валюта, курс к AMD, LastUpdatedUtc). При запросе — если
   LastUpdatedUtc старше 3 часов, дергаем CBA и обновляем таблицу; иначе отдаём из таблицы.
5. IMemoryCache в бэке — РЕШЕНО не делать сейчас (ответ Давиду дан напрямую в чате):
   DB-таблица с 3-часовой проверкой уже и есть кэш; при текущем масштабе (LocalDB, один
   инстанс) доп. in-memory слой почти ничего не даёт, а сложность (инвалидация,
   рассинхрон между инстансами при скейлинге) не оправдана. Можно добавить позже, если
   появится реальная нагрузка — не архитектурное решение "на будущее" сейчас.
6. Выбор валюты — переключатель в шапке сайта (Header), доступен ВСЕМ (без логина),
   хранится в localStorage. Backend/User НЕ трогаем (нет нового поля, нет эндпоинта
   сохранения предпочтения).
7. Тирная цена по кол-ву мест (уточнено 2026-08-06, границы больше не пересекаются):
   1-4 — база (как в БД, TotalPrice/TourDay.Price); 5-6 — +20% с округлением; 7+ — цена
   СКРЫВАЕТСЯ, показывается текст-приглашение оставить заявку. Текст 7+ живёт в
   SiteSettingCatalog (редактируется в админке без деплоя, RU/EN) — НЕ хардкод во фронте.
8. Применяется ВЕЗДЕ: каталог ("от X"), детальная страница тура, BookingCard (live
   пересчёт по счётчику гостей 1-16, счётчик уже существует в BookingCard.tsx).
9. Округление (подтверждено Давидом):
   - RUB → до ближайших 100 (макс. отклонение ~50)
   - USD/EUR → до ближайшего целого (макс. отклонение ~0.5)
   - AMD (база) → до ближайших 100
   Округление — ПОСЛЕДНИЙ шаг: тир (×1.2 если 5-6) → конвертация в целевую валюту →
   округление по правилу валюты.
10. Порядок работы — полный конвейер через субагентов (одобрено Давидом):
    backend-architect → architect(frontend) → backend-developer + frontend-developer →
    backend-tester → tester(десктоп+мобилка обязательно) → backend-code-reviewer +
    code-reviewer → update-docs (отдельное разрешение на .md уже дано в рамках этого
    конвейера).
