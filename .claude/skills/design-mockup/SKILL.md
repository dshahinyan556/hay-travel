# design-mockup

Чек-лист и процесс для дизайнерского предложения экрана/компонента, по роли
`designer`-агента. Давид не разбирается во фронтенде — решение должно быть показано
наглядно, а не только описано.

## Шаги

1. Уточни, если неясно: для кого экран, какие данные на нём, мобильный или десктоп в
   приоритете, есть ли референсы, которые нравятся Давиду.
2. Обязательно продумай и покажи ВСЕ UX-состояния, а не только "счастливый путь":
   - loading (пока грузятся данные)
   - empty (данных нет)
   - error (что-то сломалось)
   - success / основное состояние
3. Определи конкретные значения, готовые лечь в `tailwind.config.ts`:
   - палитра: 1 акцент + нейтральная шкала + семантические цвета (успех/ошибка/предупреждение)
   - типографика: шкала размеров, не больше 2 шрифтов
   - отступы: шкала, кратная 4px/8px
4. Визуализируй через Artifact (HTML/CSS-мокап) — не ограничивайся текстовым описанием
   для визуально значимых решений.
5. Дай одну обоснованную рекомендацию, а не несколько вариантов на выбор — объясни, почему
   именно так, простыми словами, без фронтенд-жаргона.
6. После согласования с Давидом — передай точные значения (не "покрасивее", а конкретные
   цифры/цвета) агентам `ui-ux-engineer`/`frontend-developer` для реализации.
