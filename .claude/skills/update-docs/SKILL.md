# update-docs

Фиксирует в docs то, что реально сделано — по правилу [[feedback_document_changes_in_docs]].

## Шаги

1. Найди папку `docs/` в корне текущего проекта (не в `Claude AI Agent/` целиком — в конкретном
   проекте, например `Hay Travel/docs/`). Если её нет — спроси у Давида через AskUserQuestion,
   создавать ли её, прежде чем писать файлы.
2. Определи, какой из существующих модульных doc-файлов относится к сделанному изменению
   (например `admin-panel.md`, `product-model.md`, `backend-api.md` — состав зависит от проекта).
   Правь **только** этот файл — не трогай остальные без необходимости.
3. Если изменение не подходит ни под один существующий файл и заслуживает нового модуля —
   спроси у Давида через AskUserQuestion, заводить ли новый файл, прежде чем создавать.
4. Формат записи в doc-файле — «что сделано и КАК сделано», а не TODO-список: закрытые пункты
   не удаляются и не превращаются в мусор, они остаются описанием реализации (архитектурное
   решение, где живёт код, причина бага, что проверено). Критерий — после изменений документ
   должен помогать новому читателю, а не мешать.
5. Добавь запись сверху в `CHANGELOG.md` того же проекта — компактно, bullet-стиль, без
   раздувания (Давид следит за расходом токенов/лимита).
6. Не переписывай README/оглавление, если изменение не меняет структуру проекта — обновляй
   его только если добавился новый doc-модуль или изменился способ поднять проект.
